# DECISIONS

## ADR-001：先完成三个 CPU 基础场景

- 日期：2026-10-08
- 根据：task01 归档的首个里程碑；仓库原先仅有文档。
- 决策：采用自建 MuJoCo CPU 基线；未明确的参数写入配置 assumptions。
- 理由：建立可核查的资产、状态和测量语义，再接 GPU/其他引擎。
- 边界：不是作者数值精确复现，不能据此给出跨引擎排名。

## ADR-002：力与时间步严格对应

- 日期：2026-10-08
- 决策：固定 Euler，使用 mj_step1/mj_step2 后尚未被刷新覆盖的求解器力，
  配对同一步起止状态；世界坐标目标物体合力与每步线动量独立对照。
- 理由：防止接触力和位姿错位一帧；峰值力必须与固定窗口冲量同时记录。
- 参考：MuJoCo 官方 simulation 文档和 mj_contactForce API。

## ADR-003：保留独立重复、失败和环境指纹

- 日期：2026-10-08
- 决策：新建唯一结果目录，拒绝覆盖；每次重建模型/数据；保留逐步原始数据与失败堆栈。
- 理由：避免手工选择结果；配置、软件、硬件和源代码哈希可追溯。
- 边界：无随机输入的重复不是置信区间估计；带诊断采样的脚本不作为吞吐基准。

## ADR-004：PhysX 沿用 Isaac Sim 镜像

- 日期：2026-10-08
- 根据：用户选择尽量沿用原文 Isaac Sim/PhysX 路径，并说明本地已有镜像。
- 决策：使用本地 Isaac Sim 6.0.1 的 CPU TGS，复用容器进程、逐次重建 USD stage。
- 数据通过 JSON 流传回宿主；仓库只读挂载，保留 image ID、实际 USD 和原生法向/摩擦冲量。
- 边界：不将 CPU TGS 与 GPU 后端的运行耗时合并排名；镜像版本并非原文版本。

## ADR-005：独立环境与真实参数回读

- 日期：2026-10-08
- 决策：Warp 固定 1.16 以匹配本机驱动；Genesis 使用 1.4.3、PyTorch 2.8、CUDA float64。
- 记录直接 MuJoCo-Warp 与原文 Newton 包装的区别；Genesis armature 显式置零并回读。
- 以原生力或冲量做逐步动量校验；失败保留，不通过增大容差掩盖测量接口遗漏。
